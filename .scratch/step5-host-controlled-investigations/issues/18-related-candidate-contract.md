## Agent Brief

**Summary:** 将 analysis 的 Related Candidate 从自由笔记提升为受校验的协议字段，并使两角色提示与 Candidate intake 契约一致。

**Current behavior:** validate_analysis_delta 接受 `related_candidates: [{"nonsense": true}]` 并作为普通笔记透传，没有 Candidate/Evidence 校验和来源关系。Verification 有 intake 校验，但系统提示遗漏 proposal_id、target、signal、next_action 等必填项；缺 proposal_id 的回复实际被整份拒绝。CandidateStore.build(extra_intake) 已存在，生产回队消费属于票 11。

**Desired behavior:** 两角色按明确的 Candidate 契约提出线索；Host 完整校验后才持久化，并提供可供票 11 幂等导入的 proposal、来源与 Evidence。非法提议整份拒绝、零部分状态与工具副作用，继续沿票 10 的反馈/重生成语义。

**Key interfaces:** normalize_intake、Analysis DeltaPlan/应用入口、Verification delta 校验与角色提示、CandidateStore.build(extra_intake)。共享契约说明或构建入口应可被票 14 的 Analysis Session 装配复用。

**Acceptance criteria:**

- [x] Analysis 将 related_candidates 作为受管协议字段校验；每项必需 proposal_id、kind、target、signal、evidence_id、next_action，并遵守既有类型/Profile/fingerprint 契约。
- [x] Related Candidate 的独立入口/位置/机制门槛与既有 Verification 规则一致；无效 kind、缺字段、未知 Evidence 等在整份动作应用或工具执行之前拒绝。
- [x] Analysis 只接纳当前 Investigation 可用的 Evidence；Verification 只接纳本次复核独立 Evidence。动作中对本次即将产生的 Evidence 的引用遵循现有预留与落盘顺序，不新增悬空持久引用。
- [x] Host 记录来源角色、Candidate/Investigation 身份及相关 Evidence；来源不由模型冒充，工件可恢复，不携带旧聊天记录。
- [x] 同一来源的重复 proposal 在恢复/重放后幂等保留；同身份异内容不静默覆盖。向票 11 明确交付稳定来源身份，便于跨不同来源同名 proposal 的回队处理。
- [x] Verification 提示完整说明必填字段及 signal/coverage 示例；Analysis 可复用相同 intake 契约说明。用提示规定的完整样例通过真实解析和领域校验，而非仅断言某字符串存在。
- [x] Action Loop 测试证明非法 proposal 整份拒绝且零部分应用/工具副作用，合法 proposal 持久化并恢复；无关 notebook 键保留原有行为。
- [x] 票 11 可从 Analysis 状态与 Verification 结果取得已校验 proposal，不必解析 Transcript 或依赖是否生成 Finding；工单 Comments 记录具体消费接口。

**Out of scope:** Candidate Queue 驱动与回队调度（票 11）、完整 Analysis 角色提示与生产 Session 装配（票 14）、重新设计去重算法、改变无效回复三次收束规则。
