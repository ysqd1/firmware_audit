# 审计工作台交互原型（可丢弃）

原型采用已确认的“精密控制台”方向，用于检查本机工作台的信息层级和操作流程。它不连接真实审计数据或控制服务；项目、候选、LLM 决策、工具返回、命令行参数和目录预检均为模拟内容。

从仓库根目录启动：

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory .scratch/audit-workbench-prototype
```

打开 `http://localhost:8765/prototype.html`。

首页以完整项目列表为主，按最近活动排序。每行展示项目名称、来源路径、运行世代、状态、当前阶段、最近活动和候选数；状态汇总压缩在列表上方。左侧只保留“审计项目”和“新建项目”两个入口。中断项目在行内提供“继续审计”操作。进入项目后可查看候选列表，再打开单个候选的逐轮 LLM 决策链。详情包含工具名称、参数、结果、错误，以及示例宿主和容器 argv。

视觉上使用冷中性底色、白色内容区和低饱和蓝色操作色，橙色仅提示需要处理的状态。表格行保持中等密度；细边界、明确字重和间距承担层级，路径、ID 和 argv 使用等宽字。避免装饰性大数字、重复的项目导航和通用仪表盘卡片。该方向只约束原型视觉，正式工作台仍须经过 spec 与工单。

新建项目交互可填写项目名和 Kali/WSL 路径，模拟零个、一个或多个固件的预检反馈，预览 `result/<项目名>/`，并演示单活动项目、打开已有项目、开始、停止和恢复。正式方向还包括从 Step0 → Step1 → Step5 启动；同一项目恢复未完成世代，封存后新开世代；关闭浏览器或重启工作台服务时审计仍继续。原型内相关操作只是状态模拟，不会运行审计。

实际 CLI argv 仅在模拟的外部工具调用中展示，并明确标为示例。正式界面应原样展示已记录的宿主与容器 argv；没有记录时标记“未记录”，协议拒绝的提案标记“未执行”。正式实现仍需按项目流程形成 spec 和 tickets。
