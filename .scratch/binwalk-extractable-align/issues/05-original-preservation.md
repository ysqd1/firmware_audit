## Agent Brief

**Category:** bug
**Summary:** 引导解包器改为只对独立工作副本解包;调用方提供的原始固件在任何路径下都保持在其原位置、字节不变(SHA-256 可验)。

**Current behavior:**
引导解包器处理"容器→continue"候选时,把候选文件硬改名进解包树(`<seq>_<原名>`,防同名输出冲突的既有设计),改名后的副本交给容器内 binwalk `-e` 解包。binwalk 的 `-e` 提取模式在成功后**消费输入文件**(团队 2026-09-10 已实测记录在案)。2026-09-20 以当前镜像最小样本复现,行为比既有记录更广:

| 样本(真实镜像实跑) | 结果 |
| --- | --- |
| gzip(有 extractor,成功路径) | 原位原件消失;树内改名副本被消费,只剩 `.extracted/` 产物;manifest 记录 renamed_to |
| zip(当前镜像自带 extractor 直接解出,未触发 7z 兜底) | 同上——原位原件与改名副本均消失 |
| 损坏 zip(binwalk/7z 均无产出,失败/空路径) | **最严重**:原位原件消失,树内改名副本也消失,manifest 记 `finalize / renamed_to=None / 均无产出`——连改名记账都没留下,文件彻底无痕 |
| 消费后 resume(manifest 驱动) | 正常完成,零重复解包(向后兼容基线良好) |

后果实例:票 04 e2e 评论(2026-09-10)记录某原厂固件被重跑消费后官方渠道已无法重新下载;2026-09-20 benchmark 案例暂存冒烟(票 16)中,一个 uimage 容器类原始固件在解包后从案例输入根顶层消失,只能靠外部留档副本恢复。注意:**即使不改名、不消费**,失败路径的改名本身也已把原件移出原位——"原位置保留"必须覆盖改名动作本身。

**Desired behavior:**
- 调用方提供的原始固件文件在解包全程保持在其原位置,内容逐字节不变;解包器只在独立工作副本上操作(binwalk 消费副本,与原件无关)。
- 该不变量对**所有**终态成立:解包成功、空产出(7z 兜底也不产出)、解包失败、单次产出超限(over_guard)、全树守卫、以及中断后 resume 完成。
- 保留的原件与树内工作副本都不得被重复入队、重复决策或重复解包:resume / scan_tree 的候选重建(manifest `files` 重建 + 树内 rglob 重扫两条路)都必须同时排除原件原位与工作副本命名。
- 工作副本在解包调用返回后即可清理(无论终态),不让副本长期滞留树内;失败/空路径下若 binwalk 自己消费了副本,清理须容忍文件已不存在(既有 missing_ok 先例)。
- manifest 如实记录:候选 → 工作副本 → 终态(含原件原位指针),失败/空路径不得再出现"文件被动过但 manifest 只记 finalize、无去向"的缺口。

**Key interfaces:**
- 引导解包器主循环的容器处理分支:现在是"硬改名原件 → binwalk",需改为"原件不动 → 副本改名/落树 → binwalk 副本"。工作副本命名须与既有簿记前缀体系一致(参考深层复扫的 `_deeprescan_` 副本 + 入口清残留 + ok 态产物归位的成套先例),并纳入 resume/scan_tree 的排除集。
- manifest 记录结构:现有键 `renamed_to` / `files` / `action` / `reason` / `done` 语义保持;新增字段(如原件原位 rel、副本路径)为**增量**字段,旧格式 manifest 无需迁移。
- `resume` 模式的既有契约("固件文件可能已被改名进解包树,不检查存在性")保持成立;旧格式 manifest(含"原件已被消费"的历史运行)必须能继续 resume——本票只改变新运行的写入行为,不追溯旧产物。
- `main` 流水线调用方:解包入口签名不变(调用方无需复制固件——副本化解包是解包器内部职责)。

**Acceptance criteria:**
- [ ] 最小样本实跑(真实 binwalk 镜像):gzip / zip / 损坏 zip 三类样本解包后,原位原件存在且 SHA-256 与解包前一致;树内产物与现行为等价(产物集不变)。

- [ ] over_guard 路径(可用既有 fake extractor 注入模拟,不必真实构造 5 万文件):原位原件存在且不变,增量产物删除语义不变。
- [ ] 中断恢复:解包中途杀进程后 resume,原位原件存在且不变;旧格式 manifest(现状格式,含 renamed_to 指向已消费文件的记录)resume 成功且零重复解包(以 fixture 固化,防回归)。
- [ ] 保留的原件与工作副本不被重复入队:resume 与 scan_tree 模式下,对已解包案例重跑,manifest 记录数与产物集不变(零新增解包)。
- [ ] 实际 binwalk 行为用当前镜像验证并把结论写入本票评论(已知偏差:当前镜像 zip 有 extractor 直接解出,"zip 无 extractor 走 7z 兜底"的旧前提已不成立;7z 兜底路径的消费行为需在修复中实测确认)。回归测试允许以 fake extractor 模拟"输入被消费"。
- [ ] 全套件绿(含既有 Step1 全部路由/守卫回归);零内容守卫语义不变。

**磁盘开销说明(设计须内建,评论须记录实测):**
- 增量成本 = 解包期间每个容器文件多一份副本,解包调用返回后即删,峰值 ≈ 最大单容器文件体积(本仓库实际负载为数十 MB 量级,相对解包产物树数百 MB 可忽略);原件保全本身零开销(原地不动)。

- 不追旧账:不恢复历史上已被消费的固件,不为旧产物补写 manifest。
