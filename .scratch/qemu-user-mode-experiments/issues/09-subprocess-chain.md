# 09: 子进程链支持与约束

**What to build:** 在票 15 的受约束 PRoot + QEMU 后端上支持原固件自主派生 shell/辅助程序。覆盖进程数上限、原固件与声明运行目录的执行边界、整次执行的超时清理及可信链路记录；不使用宿主 shell 替代。不能只依赖进程组收割；必要时销毁整个会话容器。完整原链验收与运行边界均须通过，失败保留具体阻塞，不静默收窄范围。

**Blocked by:** 15, 07, 08

**Status:** wontfix

**Superseded by:** [16](16-single-execution-chain.md)

> 已合并，不再单独执行；wontfix 仅表示本旧票停止调度，不表示取消需求或已实现。原正文、AC 和依赖保留为历史，现行要求以替代票为准。

机制更新：采用 PRoot + QEMU，以票 15 的实现和边界验证为前提。票 04 的裸 QEMU 失败作为历史对照，不再作为本路线不可行的结论。路径约束覆盖原件只读映射与声明运行目录中的受支持固件程序，不把可信后端装载桩当作任意 guest 可执行文件。

- [ ] 原 ARM shell 自主派生动态及静态辅助程序、MIPS 对照通过；另测非 shell 父程序直接发起执行，区分真实固件证据与合成机制夹具
- [ ] 正式会话下验证固件内部发起的 `/host-rootfs` 与别名绕过被拒，不能仅检查模型输入；进程上限覆盖整次执行，后台派生和异常退出不能漏清理
- [ ] 台账区分固件目标、PRoot/QEMU、prooted 桩，验证短命子进程的观测覆盖；缺失信息明确标记，不用轮询快照宣称完整链。机制性拒绝不误归为目标崩溃或漏洞反证

- [ ] 命令注入类场景实测：目标派生的固件 shell/辅助程序在仿真内执行并留观察记录
- [ ] 进程数上限生效；白名单外路径的派生被拒并记录
- [ ] 该次执行超时/停机时整条链被确认清理；覆盖脱离原进程组的子孙进程，必要时销毁会话容器，无遗留进程
- [ ] 链进程（数量、路径）入该次执行台账
- [ ] 离线测试 + 门控集成测试；全量套件绿
