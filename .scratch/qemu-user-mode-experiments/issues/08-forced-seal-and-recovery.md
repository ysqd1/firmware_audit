# 08: 强制收口与遗留容器恢复

**What to build:** 调查任何终态（正常完成 / 预算耗尽 / 中断）下，Host 强制停机并封存全部开启会话，不依赖 agent 自觉调用停机；恢复路径强制收割遗留容器；"中断即会话死亡"语义落地：被中断会话标中断并分别记录清理结果，无法确认清理时标"清理不确定"、运行目录产物留档供复查但不进新会话、续跑开启新会话、已持久化的执行不重复扣名额。

**Blocked by:** 07

**Status:** wontfix

**Superseded by:** [17](17-stateful-session-recovery.md)

> 已合并，不再单独执行；wontfix 仅表示本旧票停止调度，不表示取消需求或已实现。原正文、AC 和依赖保留为历史，现行要求以替代票为准。

修订：中断状态与清理结果分别记录。中断必定使会话死亡，但只有无法确认清理时才标记“清理不确定”，不能将所有中断都混为清理失败。

- [ ] 覆盖 PRoot tracer、QEMU、短命及后台子孙进程；验证客户端死亡不等于执行停止，按需销毁整会话容器，保留输出与清理证据
- [ ] PRoot 临时桩、bind 残留和旧运行目录不隐式进入新会话；清理确认失败时不得复用旧容器继续执行

- [ ] 三种终态强制封存：会话开启状态下调查结束，容器被停、台账被封存，无需 agent 调用停机
- [ ] 恢复路径强制收割遗留容器（含 Host 进程死亡后遗留的孤儿容器），收割行为有记录
- [ ] 中断即会话死亡：恢复后旧会话不可继续执行，留档可查，新会话独立计数
- [ ] 中断发生在开启/执行中/输出采集/停机各边界的恢复测试：状态与台账一致，不伪装正常结果
- [ ] 全量套件绿
