# 15: PRoot 后端接入与运行边界验收

**What to build:** 将 [PRoot 调查](../investigation/proot-arm-chain-2026-09-22/README.md) 的成功机制变成可复现、受约束的执行后端，作为票 06 的前置。按 [spec](../spec.md) 固定 PRoot/QEMU/镜像，更新静态预检，并在真实 ARM/MIPS 探针上证明原执行链及运行边界。此票补充已完成的 03/05，不重开或覆盖旧成果；不包含 Host 会话 API、业务通路验收或 NVRAM 模板。

- [ ] 从已测 PRoot 5.4.0 + QEMU 5.2 + bookworm-slim 组合复现，固定基础镜像 digest、源文件校验值、版本与重建命令；保留旧镜像可追溯身份。若调整组合，重跑完整矩阵，不能直接推定新版更兼容
- [ ] 原 ARM shell 自主派生原动态程序及静态辅助程序通过，MIPS 对照通过；保留实际程序身份、输入输出、命令与版本，不能用宿主 shell 或手动拆调用冒充
- [ ] 实现运行时的 guest 执行边界；实测拒绝 `/host-rootfs` 原生 shell/工具/额外 QEMU 及其规范化、符号链接、适用 proc/fd 别名与执行系统调用变体。包含由固件内部构造路径的反例，不能仅验证工具入参；可信后端必需程序与 guest 可执行程序分开授权
- [ ] 明确所用约束机制、覆盖范围及不能观测的情况；若上一项无法满足，本票保持未完成、06/09 继续阻塞，提交具体证据，不放宽约束或把“发现风险”当成“风险已解决”
- [ ] 显式运行根、最小 bind 与必需设备；原始材料只读、运行目录可写、Evidence/其他 target/docker socket 不可达；断网、默认 seccomp、无 privileged 和额外 capability 实测通过
- [ ] 每次启动独立 PRoot；超时、杀 tracer、杀 Docker 客户端分别验证残留及清理，必要时整体销毁容器；记录临时桩/挂载残留处理和不可确认状态
- [ ] 静态预检补后端版本/身份及所测矩阵；不执行 guest、不创建会话。ARM 链能力仅对验证条件成立，NVRAM 等依赖仍独立阻塞
- [ ] 提供供 06 使用的后端契约及身份材料：区分原固件、PRoot、QEMU、prooted 装载桩，不靠 cmdline 或单一 exe 指纹证明实际链路
- [ ] 离线契约检查与真实 Docker 门控验证，保留命令、输出及限制；不调用 LLM、不读取 GT，不以集成跳过关闭本票
