## 目标

让 Analysis/Verification 在静态证据不足、适合执行实验时，运行原始固件中的单次程序或 CGI，并取得可独立复查的行为证据。第一阶段不启动持续运行的网络服务，不做整机模拟，不强迫每个候选进行动态测试。

已确认包含该程序启动的有限 shell/辅助程序执行链。子进程机制须在既定隔离和不修改宿主全局 binfmt 的约束下验证；不以宿主 shell 替换固件 shell 冒充原执行链成功。若机制不可行，先报告阻塞并重新讨论范围。

## 建议交付组成

1. 固定版本的 QEMU 用户态执行环境。依据现有案例，优先支持 ARM32 小端与 MIPS32 大端；还需验证具体 ABI、加载器及 NVRAM 适配库兼容性，不承诺所有同架构程序均可运行。
2. 独立的 QEMU 检查/执行工具，与现有 sandbox_verify 共享底层隔离、超时和证据能力。sandbox_verify 保留脚本实验职责，不把模型自行拼接 QEMU 命令作为唯一入口。
3. 预定义适配模板：目录/配置/参数/CGI 输入与有限 NVRAM 读取。具体 NVRAM API 必须由真实库和调用点确定；不能只凭函数名推断签名、内存所有权或缺失键语义。
4. 按世代、角色、调查和实验身份分开的实验材料。每次从原件和声明的适配重建运行副本；保存输入、适配、输出及 digest，历史状态不会隐式带入。

## 建议调用与证据契约

检查阶段报告目标架构、加载器、可解析依赖和模板是否适用，不执行目标程序。预检通过仅代表可以尝试启动，不代表没有运行时依赖。

执行输入包括目标工具路径、运行根、argv（含必要的程序调用名）、工作目录、受管环境变量、标准输入或输入文件，以及模板参数和来源引用。模板参数与漏洞测试输入分开：测试数据可以由模型构造，假设中的设备配置不能被冒充成真实配置。清理继承的宿主环境；QEMU 加载器前缀不作为文件系统隔离措施。

输出区分正常退出、非零退出、目标信号、超时、准备阻塞、运行时依赖阻塞和执行设施失败；原始退出码及日志始终保留。工具不直接返回“漏洞成立/不存在”。退出码、信号或字符串本身不足以证明缺陷原因，不把环境产生的崩溃误当目标漏洞。

每次保存：目标与依赖身份、镜像/QEMU/模板版本、规范化输入、适配依据、运行限额、实际输出和结果分类。大日志有总量上限，截断及输出上限触发可见；原始固件只读，输出只进入实验区域。第一阶段维持断网、不注册宿主全局 binfmt，不将 Docker socket 或其他 target 挂入实验环境。

## 资源与恢复规则（时间和执行次数已确认，其余待规格收敛）

- 单次实验默认 60 秒，允许请求至多 180 秒；还受案例剩余活动预算约束。预检/准备与目标运行的耗时都记录，不只计算被测程序时间。
- 已确认每个 Analysis Investigation 最多 4 次目标执行，每个 Verification Case 独立最多 4 次；正常输入对照、异常测试和复现都计数。时间与次数是可配置初始策略，未经实测校准。建议预检不占目标执行名额，但仍计入现有工具尝试与活动时间预算。
- 容器 CPU/内存/进程数与输入输出大小须设置有限上限；具体数值待最小真实样本验证后写入版本化配置，不能把待验证数值当已确认要求。
- 不自动循环修复或重复执行。失败反馈给模型，模型可在预算内选已支持模板或改测试输入；相同阻塞不能靠无变化重试消失。
- 执行中断不自动重放，先保留 interrupted 和可取得的日志；模型若需要复现，显式发起新实验。清理规则必须覆盖目标派生进程和异常退出后的容器，不只终止宿主 Docker 客户端。

## 独立复核与验收（交付门槛已确认，步骤待核查）

Verification 可以看到定位所需输入与适配来源，但重新取得关键材料、核对适配依据，在自己的干净环境中独立执行；不能直接引用 Analysis 的运行结果充作本次独立支持。

验收至少覆盖正常执行与对照输入、真实固件单程序/CGI、有限 NVRAM 读取模板、未知配置和缺依赖阻塞、信号/超时/中断、输出限制、状态不继承和独立复核。合成接口夹具证明实现契约，真实固件样本证明集成可用；不得用合成程序成功替代真实固件验收。真实样本与运行通路仍待核查，不预先保证具体路由器 CGI 一定跑通。

Q8 A 已确认的最低交付门槛为：真实固件的一条单次程序/CGI 业务通路、可检查输入输出、正常输入对照、干净环境复现，以及有限 NVRAM 模板的真实接口兼容性。有限子进程能力须有对应执行链验收；具体样本选择仍待核查，不把单程序启动成功当作子进程能力已验证。安装成功、版本输出或合成测试单独通过不能关闭第一阶段验收。

规格还须封闭脚本工具绕过 QEMU 计数的路径，明确按调查/复核分开的持久化台账，以及实验内派生进程与独立顶层测试的边界。共用执行底层不强制共用镜像。运行副本与权威证据存储分开，目标不能写历史证据；超时需清理容器及派生进程并保留可取得的输出、清理状态和局限。

保留现有 gen-0001 结果，新能力只在显式新运行中评价。GT 仍在发现工作区之外，不把已知漏洞函数或输入注入生产提示词。集成可用与审计质量改善分别验收：后者需要后续固定条件对照，不能由“QEMU 返回成功”推导。

## 本轮决定与规格准备

2026-09-21，用户以“两个都同意”确认独立 QEMU 工具分工，以及默认 60 秒/上限 180 秒、Analysis 和 Verification 各 4 次目标执行的初始预算。不重复征询这两项决定。

随后用户以“Q7 A Q8 A”确认有限子进程执行链和真实固件通路验收。后续 spec 继承这些决定，技术验证不通过时不得擅自降低验收标准。

只读核查已确认 target/6、7 的 NVRAM 接口族有差异，target/7 包含 bcm_nvram 和 envram 包装层；函数名不能证明 ABI 和行为一致。target/8 此次未发现相应动态符号，不能充作 NVRAM 模板验收样本。详见设计访谈事实部分。

下一步规格需明确首批架构/ABI 支持表、模板接口及缺失键语义、独立复核材料、工具参数、预算计数与恢复规则、隔离和验收标准。无法核实的接口明确排除或设为前置调查项，不写成已支持能力；不需要用户猜函数签名。整体方案确认、接口核查及规格收敛后再拆票。
