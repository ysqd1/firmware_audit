# Spec: target/5 e2e 实测修复(五项)

> 2026-09-11 由 target/5(D-Link DIR-882)全流水线 e2e 实测驱出,grilling 六问定稿(Q5 现状不动关闭)。
> 根因全部有复现证据,详见各工单。

## Problem Statement

一次全新的端到端审计中,操作者遭遇五类可避免的损耗:①CVE 扫描整块能力静默丢失(配置在但没接线,也无任何告警);②一份合格的侦察成果因 JSON 转义瑕疵被整体降级,触发数十万 token 的全额补跑;③终端与简报把侦察观察点误标成 "findings",违反项目词汇纪律,误导对运行状态的判读;④Agent 按 r2 函数名取证时两次撞墙,被迫浪费轮次换地址重试;⑤报告对账守卫因 LLM 改写标题报出 4 条假警报,守卫可信度受损。

## Solution

①一处配置接线 + 启动预检显式告警,让 CVE 缓存缺失从"静默失败"变"开场警告";②宽容 JSON 提取器增加一档保守的过度转义修复,修不好照旧降级;③显示层为 recon 使用"观察点"标签;④r2 反汇编工具在函数名形如 `fcn.<hex>` 时自动按地址执行;⑤报告红线"finding 标题逐字复制"+ 对账匹配加模糊兜底,假警报消失而真差异(改判级、漏条目)照样被抓。

## User Stories

1. 作为审计操作者,我希望 Step5 启动时在 CVE 缓存为空的情况下收到显式警告,以便我知道本次审计将没有 CVE 数据、并且知道一行 env 就能修。
2. 作为审计操作者,我希望通过一个环境变量把预热好的共享 CVE 库接到任意新 target,以便不必每个 target 重新下载 NVD 库。
3. 作为审计操作者,我希望侦察产出的转义瑕疵不至于推翻整份侦察成果,以便补跑预算留给真正的情报增量。
4. 作为审计操作者,我希望终端监控和任务简报里 recon 阶段显示"观察点"计数而非 "findings",以便我按项目词汇正确判读各阶段产物。
5. 作为审计 Agent,我希望按 r2 函数名发起的反汇编在名字跨会话失效时自动退到等价地址,以便不浪费轮次手动换写法。
6. 作为审计操作者,我希望报告与工件的对账只在我真的改动了事实(severity/verified/漏条目)时才报警,以便每条 unmatched 都值得人工去看。
7. 作为维护者,我希望以上每一项修复都有先红后绿的回归测试锁住,以便同类问题不再复发。
8. 作为维护者,我希望 JSON 修复档是保守的(修不好就维持降级),以便不存在"修出来的错误数据"混进工件链。

## Implementation Decisions

- **CVE 缓存(票01)**:`.env` 增配共享缓存目录指向既有预热库;Step5 启动时(工作区解析后)做一次预检——resolved 缓存目录内无 cvedb 库文件即在 summary 输出显式警告行(不中断、不降级)。自动回退共享库/只读挂载不做(写并发另议);token 熔断不做(Q5 用户拍板现状不动)。
- **JSON 过度转义修复(票02)**:宽容提取器加第二档——原文解析失败且错误为 Invalid \escape 时,把形如 `\\"` 的双重转义归一为 `\"` 后重试;**接受条件三合一**:修复后能解析 + 通过 finding/survey 形状校验 + 原文确属该错误类型,任一不满足维持现有降级路径。纯函数,零 LLM、零新依赖。
- **显示标签(票03)**:recon 分支的完成行与简报文案改用"观察点"计数标签(数据源不变,仍是 high_risk_areas 数量);analysis/verification 的 "findings" 标签不动。纯显示层,提示词不涉改。
- **r2 名址转换(票04)**:反汇编工具入口加一个纯函数:目标名匹配 `fcn.<hex>` 即转 `0x<hex>` 地址再执行,LLM 无感、提示词不动;其余名字形态行为不变。
- **对账双侧修(票05)**:①编排层系统提示词(报告生成方)加红线:报告条目标题必须逐字复制 verified finding 标题,禁止缩写/改写;②对账匹配在归一化精确相等失败后加兜底:标题前缀一致或重合度 ≥0.8 视为同一 finding,仍失败才记 unmatched。file/severity/confidence/verified 的确定性比对语义不变。

## Testing Decisions

- 只测外部可观察行为:解析器吃文本出结构、工具吃参数出 ToolResult、对账吃两份文档出清单、显示吃事件出行——不测内部调用序列。
- 五项全部落在**既有测试缝隙**,不开新缝:数据契约纯函数测试(票02)、编排/显示守护测试(票03、票05 匹配器)、r2 工具测试(票04)、CLI 工具与汇总测试(票01 预检)。
- 先红后绿:票02 与票05 直接用 target/5 实测产物做缩样 fixture(降级 JSON 第 8 行样本、67/98 字符标题对照),先复红再修。
- 先例:observ 预算两票(ticket 01/02)的同款测法——fixture 缩样 + 断言契约而非错误文案。

## Out of Scope

- Token 经济学(Q5):不加熔断、不降补跑上限,现状不动(2026-09-11 用户拍板)。
- CVE 共享库自动回退与只读挂载(写并发语义需单独设计)。
- 降级前 LLM"只重发 JSON"的挽回收案(若票02 修复档实测不够再立项)。
- 显示层之外的词汇清扫。

## Further Notes

- 实测基线:target/5 全流水线 EXIT=0,79 分钟,451 万 prompt + 16.4 万 completion token,报告 7 条已证实 + 1 条 high 候选留人工;8/8 复核闭环。流水线主体(解包、编排弹性、每疑点一实例、截断回读、LLM 重试)实测健康,本批五票全是边角损耗修复,不动架构。
- 工单间无阻塞边,可任意顺序实现;建议按 01→02→05→03→04(价值序)。
