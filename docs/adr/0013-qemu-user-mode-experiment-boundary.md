# 0013 — QEMU 用户态实验允许有依据的环境适配

2026-09-21，用户确认第一阶段引入 QEMU 用户态模拟，用于单次执行的固件程序或 CGI；常驻网络服务的运行测试后置。QEMU 是沙箱中的执行能力，不替代 Docker 隔离，也不因此引入跨调用常驻容器。当前确认的是设计边界，尚未实现或授权修改产品代码。

实验先使用原始目标程序和固件自带的加载器、库。允许准备目录、配置及有明确依据的依赖模拟，逐项保留来源、改动和适用条件；不自动修补认证、输入过滤、边界检查等与漏洞成立有关的程序逻辑。原始固件保持不变，环境适配只作用于独立实验副本。未知依赖的假设可用于探索，但不能仅凭该实验生成 confirmed；需要证明假设成立，或将结论限定在已有证据支持的条件内。

选择此边界是因为完全禁止环境适配会使厂商依赖阻断有价值的实验，而不受约束的修补会让实验结果脱离原程序的实际行为。程序启动失败不是漏洞不存在的反证，崩溃也不自动证明漏洞成立。沿用 ADR-0012 的独立复核、证据引用和封存规则；实验成功不直接越过 Claim 复核门槛。

同日用户进一步确认：第一阶段仅通过预定义适配模板实施自动环境适配。Agent 可依据材料自主选择已支持模板并填写参数，不需要逐次人工批准；不自由生成替代库或厂商接口代码。模板未支持的依赖明确记录为运行阻塞，不临时编造实现。

首批模板范围进一步确认为：基础目录、配置文件、参数和 CGI 输入准备，以及有限的 NVRAM 配置读取模拟。NVRAM 只支持明确列出并经过验证的接口，配置值须来自固件配置或其他可核查证据；未知值不随意补空，不统一返回成功。具体函数、ABI、缺失键语义和支持的固件依赖尚需核查，不把模板范围确认等同于所有厂商接口均受支持。

用户选择每次实验从干净运行环境重建。脚本、输入、适配方案和历史结果保留供复查，但被测程序上次产生的运行文件不自动进入下次实验；复用文件必须显式列为本次输入并保留来源。此选择约束实验状态，不引入常驻容器，也不把历史结果当作新的独立观察。

调用时机确认为按证据缺口选用：Analysis 或 Verification 在需要观察真实程序行为时请求 QEMU，不要求每个适用架构的二进制候选都执行模拟。工具说明与角色指令应解释适用场景；运行受阻记录缺失条件并允许继续静态取证，不把模拟失败视为漏洞反证，也不将动态实验列为所有 Finding 的必经门槛。

工具分工已确认：新增独立的 QEMU 检查/执行入口，保留 sandbox_verify 的脚本实验职责，两者共享底层隔离、超时与证据能力。具体工具数量、参数及结果 schema 在规格中明确。

初始执行预算已确认：单次目标执行默认 60 秒、上限 180 秒，每个 Analysis Investigation 最多 4 次，每个 Verification Case 独立最多 4 次。正常输入对照、异常输入测试和重复复现均占执行名额，并受案例总预算约束；失败不自动重试。上述数值是可配置的初始策略，尚未通过真实实验校准，不能宣称足以覆盖所有程序。

具体架构支持、首批模板接口清单、CPU/内存等资源限额、工具参数和工件 schema 尚待规格确认。本 ADR 不授权修改产品代码，不要求迁移或重跑既有 sealed 世代。

用户进一步以“Q7 A Q8 A”确认执行范围与验收门槛：单次实验包含原程序启动的有限 shell/辅助程序执行链，仍不包含常驻网络服务。子进程机制须在不修改宿主全局 binfmt 的既定约束下验证；不得以宿主 shell 替换固件 shell 后宣称原执行链已复现。无法实现时记录具体阻塞并重新讨论范围，不静默删去已确认能力。

第一阶段交付须跑通真实固件的一条单次程序或 CGI 业务通路，保留可检查的输入输出、正常输入对照，并在干净环境中重复取得结果。有限 NVRAM 模板须通过真实接口兼容性验证。安装成功、版本输出或合成测试通过不足以单独完成验收；不要求所有案例跑通或命中 GT，也不把业务通路运行成功等同于漏洞成立。具体样本和实验步骤由后续技术核查及规格明确。

同日晚些时候的规格访谈第二轮中，用户逐项确认会话制执行模型：会话内运行目录状态跨 ReAct 轮积累、会话之间干净重建、一次性单发实验为只含一次执行的会话特例；常驻范围仅限环境常驻、常驻服务后置；本决定修订入本 ADR 而非另立新档。据此对前文作两处修订。其一，"每次实验从干净运行环境重建"修订为"每次会话干净重建"：QEMU 工具采用会话生命周期（开启会话、会话内执行、停机封存），会话即实验单位并占用执行名额；会话运行目录内的状态跨 ReAct 轮积累，登录、写配置、触发这类多步通路在同一会话内完成。其二，"不引入跨调用常驻容器"修订为"容器生命周期与会话一致"：会话期内容器跨工具调用存活，会话结束即拆除；两次执行之间不允许目标进程存活，常驻网络服务（跨轮存活的目标进程）仍属后置范围。

预算语义相应细化：每次目标执行仍默认 60 秒、上限 180 秒；执行名额按会话计，Analysis Investigation 最多 3 个会话、Verification Case 独立最多 3 个（同日由 4 收紧为 3）；会话内执行次数上限为显式预算参数，随 QEMU 预算块走既有分层解析、`.env` 环境层可覆盖，缺失或非法值回落默认，临时默认值 4，最终默认值由真实样本校准定稿；不另设会话级活动时长上限——空闲不计量前提下活动时长由执行次数与单次超时自然封顶，执行耗时仍逐条计入案例活动时长预算；失败不自动原样重试的约束不变。

会话制引入强制收口义务：调查无论正常完成、预算耗尽还是中断，Host 都强制停机并封存全部开启会话，不依赖 agent 自觉调用停机；恢复路径对遗留容器强制收割，无法确认清理时按既有"清理不确定"分类记录，不伪装为正常结果。中断即会话死亡：恢复不复活被中断的会话，其运行目录产物留档供复查但不进入新会话；续跑开启新会话，已持久化的执行不重复扣名额。会话台账（按序记录每次执行的声明输入、输出与 digest）为实验工件；可复现性由"声明的输入"扩展为"声明的输入加上被完整记录的执行序列"，Verification 独立开启会话、按台账逐条重放关键执行序列以取得独立观察。会话常驻不改变工具的受控入口性质：不赋予模型自由 shell，路径白名单、参数校验与能力授权不变。

## 2026-09-22：采用 PRoot + QEMU，保留接入前的边界验收

用户在 [PRoot 调查](../../.scratch/qemu-user-mode-experiments/investigation/proot-arm-chain-2026-09-22/README.md) 后明确选择此路线，并要求同步 spec 和剩余工单。原固件父程序继续自主派生子程序，PRoot 处理执行请求并接入 QEMU；无需修改宿主 binfmt，也不更换固件 shell。采用路线不等于第一阶段已经交付。

调查在 bookworm-slim 上验证 PRoot 5.1.0/5.4.0 与现有 QEMU 5.2 的组合。实现从 5.4.0 + 5.2 的实测组合复现并固定版本；不能将裸 QEMU 新版实验视为新版与 PRoot 的组合验证。Docker 仍是隔离边界，会话容器保留、每次执行重建 PRoot 实例、仅运行文件跨轮保留；原有预算、独立复核、适配和不修改原件约束不变。

明确代价是 `/host-rootfs` 暴露容器原生程序、临时装载桩改变进程身份观察、ptrace 带来兼容性和清理要求。调查证明这些问题存在，没有证明工具入口的前缀白名单能约束 guest 内部派生。因此新增票 15，先复现并封闭实际运行时的绕过路径，再接入票 06；不能靠输入校验宣称已封闭，也不能自动申请 privileged 或放宽能力。若约束无法满足，记录具体事实并保持依赖票阻塞，不擅自降低原执行链或隔离要求。票 09 扩展链路约束与观测，票 14 验收真实业务通路。

已完成票 01–05 保留历史结论，不将其标成新后端已经完成。后续以 [spec](../../.scratch/qemu-user-mode-experiments/spec.md) 和 [实施顺序](../../.scratch/qemu-user-mode-experiments/execution-order.md) 为准。

## 2026-09-22：PRoot raw execveat 正式接入

原型验证完成后，票 16 将 PRoot 5.4.0 的 raw `execveat` deny 补丁接入正式
`qemu-exec-v2` 镜像。QEMU tracee 在路径解析前收到 `EACCES`；实现覆盖
amd64 host syscall 表、seccomp/ptrace 过滤和 fallback 路径，不重写 guest 合法
raw `execveat`。镜像以补丁 SHA-256 标签建立身份，预检与会话入口拒绝缺少或
漂移的镜像；普通 `execve`、ARM/MIPS 派生链仍按票 16 的真实 Docker 回归验收。

此前“尚未实现或授权修改产品代码”的表述描述的是本 ADR 建档时点，已由本节
记录的正式实现状态取代；实验边界、证据限制和不读取 GT 的约束不变。

## 2026-09-23：预算默认值按真实样本校准定稿（票 19）

约 0.34s、封存约 0.17s，测试数据见
`.scratch/qemu-user-mode-experiments/investigation/ticket19/`。4 覆盖已
观测最大会话需求（3）加 1 次余量，对照/异常/复现逐次计数不变；60 秒默认
执行预算对实测负载有逾 300 倍余量，180 秒硬上限与重试语义维持不变，无需
